初试 FastAPI：接口设计、校验与异常处理

2026/4/25 后端 FastAPI Python API设计 Pydantic

FastAPI 适合做什么

FastAPI 适合快速构建 Python Web API，特点是：

  • 基于类型注解做参数解析和校验。
  • 使用 Pydantic 定义请求和响应模型。
  • 自动生成 OpenAPI 文档。
  • 原生支持 async，适合 I/O 密集型接口。

在 AI 应用或后端管理服务中，FastAPI 很适合做 RAG 服务、模型调用网关、内部工具 API 和轻量管理后台。

基础路由

from fastapi import FastAPI

app = FastAPI(title="Demo API")


@app.get("/")
async def read_root() -> dict[str, str]:
    return {"message": "Hello, FastAPI"}

@app.get("/") 把 HTTP GET 请求映射到函数。函数返回的 Python 对象会自动序列化为 JSON。

参数类型

路径参数

from fastapi import Path


@app.get("/items/{item_id}")
async def read_item(
    item_id: int = Path(..., ge=1, description="商品 ID"),
) -> dict[str, int]:
    return {"item_id": item_id}

路径参数是 URL 的一部分，例如 /items/100。类型写成 int 后，FastAPI 会自动做类型转换和校验。

查询参数

from fastapi import Query


@app.get("/items")
async def list_items(
    skip: int = Query(0, ge=0),
    limit: int = Query(20, ge=1, le=100),
) -> dict[str, int]:
    return {"skip": skip, "limit": limit}

查询参数适合分页、筛选和排序。对 limit 设置上限是必要的，否则容易被大请求拖慢服务。

请求体参数

from pydantic import BaseModel, Field


class ItemCreate(BaseModel):
    name: str = Field(..., max_length=100)
    description: str | None = Field(default=None, max_length=255)


@app.post("/items")
async def create_item(item: ItemCreate) -> ItemCreate:
    return item

请求体使用 Pydantic 模型定义，字段校验会自动执行。校验失败时，FastAPI 默认返回 422。

响应模型

接口不要直接把数据库对象原样返回，应该定义响应模型，控制输出字段。

class ItemResponse(BaseModel):
    id: int
    name: str
    description: str | None = None


@app.get("/items/{item_id}", response_model=ItemResponse)
async def get_item(item_id: int) -> ItemResponse:
    item = await item_service.get_by_id(item_id)
    return ItemResponse.model_validate(item)

这样可以避免把内部字段、敏感字段或无关字段暴露给前端。

异常处理

业务不存在时，不要返回 None 或空对象，应该返回明确的 HTTP 状态码。

from fastapi import HTTPException, status


@app.get("/items/{item_id}", response_model=ItemResponse)
async def get_item(item_id: int) -> ItemResponse:
    item = await item_service.get_by_id(item_id)
    if item is None:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail="Item not found",
        )
    return ItemResponse.model_validate(item)

异常处理的目标是让调用方能明确知道失败原因，而不是猜测接口含义。

项目结构建议

小项目可以从单文件开始，但一旦接口变多，就应该拆分职责：

app/
  main.py
  routers/
    items.py
  schemas/
    item.py
  services/
    item_service.py
  repositories/
    item_repository.py

职责划分：

  • routers：只处理 HTTP 入参、出参和状态码。
  • schemas：定义请求和响应结构。
  • services：承载业务逻辑。
  • repositories：封装数据库访问。
