什么是 Agent：从 LLM 到可控自动化系统

2026/5/17 AI应用 工程化 Agent Workflow LLM MCP

Agent 是什么

Agent 本质上是一个能围绕目标自主推进任务的 AI 系统。它和普通 LLM 对话最大的区别是：普通 LLM 更像一次问答，Agent 则会规划步骤、调用工具、读取上下文、根据结果继续调整动作。

可以用一句话概括：

LLM 负责理解和生成，Agent 在 LLM 之上增加了目标、工具、记忆和行动闭环。

核心组件

1. LLM：决策大脑

LLM 负责理解用户目标、分析当前状态、决定下一步动作，并生成最终回复。Agent 的规划、工具选择和错误修正，本质上都依赖 LLM 的推理能力。

2. Tools：外部能力

工具是 Agent 连接外部系统的接口，例如：

  • 搜索网页。
  • 查询数据库。
  • 读写文件。
  • 调用业务 API。
  • 创建工单或发送消息。

工具决定 Agent 能做什么，也决定了风险边界。读操作通常风险低，写操作必须增加确认、权限和审计。

3. Memory：记忆系统

记忆通常分为两类：

  • 短期记忆：当前对话上下文，适合保存本轮任务状态。
  • 长期记忆：跨会话保留的重要信息，通常需要检索或结构化存储。

生产系统里不能无节制保存记忆，需要考虑隐私、权限、过期和可删除能力。

4. Planning：规划与执行

常见模式包括：

  • Plan-and-Execute：先生成计划，再逐步执行。适合步骤清晰的任务。
  • ReAct：边观察、边思考、边行动。适合需要根据环境反馈动态调整的任务。

Agent、Workflow 和 Tool 的区别

概念 作用 特点
Tool 一个具体能力接口 边界清晰，输入输出明确
Workflow 预定义流程 稳定、可控、适合生产主链路
Agent 自主决策系统 灵活，但风险和不确定性更高

工程上不要把所有事情都交给 Agent。更稳的做法是用 Workflow 固定主流程，在分类、总结、工具选择等局部节点引入 Agent 能力。

MCP 是什么

MCP（Model Context Protocol）可以理解为 AI 应用连接外部数据和工具的一种协议。它主要有三类角色：

  • Host：承载 AI 的应用，例如 IDE、桌面应用或聊天产品。
  • Client：Host 内部负责和 MCP Server 通信的组件。
  • Server：对外提供工具、资源或提示模板的服务。

MCP 不是 Agent 本身，而是 Agent 连接外部能力的一种标准接口。

生产环境的可控性

Agent 真正落地时，重点不是“能不能自动做事”，而是“自动做事是否可控”。

需要关注：

  • 权限边界：哪些工具能调用，哪些参数允许传入。
  • 人工确认：写文件、发消息、下单、部署等副作用操作必须确认。
  • 日志审计：每一步工具调用都要记录输入、输出和错误。
  • 失败降级：工具失败、模型超时、结果不可信时要有 fallback。
  • 循环限制：避免 Agent 无限重试或无限规划。

面试表达

可以这样回答：

我理解的 Agent 是在 LLM 基础上加入工具调用、记忆、规划和执行闭环的系统。它比普通聊天模型更主动，但生产环境不能完全放任自主执行。更稳妥的工程做法是用 Workflow 固定主流程，在需要灵活判断的节点嵌入 Agent，同时对工具权限、写操作确认、日志审计和失败降级做约束。

总结

Agent 的价值是把模型从“回答问题”推进到“完成任务”。但它的工程难点也来自这里：只要能行动，就必须考虑权限、副作用、可观测性和失败恢复。
