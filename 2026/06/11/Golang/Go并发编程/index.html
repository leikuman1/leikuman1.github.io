Go 并发编程：goroutine、channel 与同步控制

2026/6/11 后端 Go 并发 goroutine channel 工程化

进程、线程、协程

理解 Go 并发前，先区分三个概念：

  • 进程：操作系统资源分配的基本单位，有独立地址空间，隔离性强，但创建和切换成本高。
  • 线程：CPU 调度的基本单位，同一进程内线程共享内存，通信方便，但要处理竞态和锁。
  • 协程：运行在线程之上的轻量执行单元，由语言运行时调度，创建和切换成本更低。

Go 的 goroutine 可以理解为由 Go runtime 调度的轻量协程。它适合大量 I/O 并发场景，但不代表可以无节制创建。生产环境仍要考虑连接数、内存、限流和退出控制。

Go 并发模型

Go 常见并发思路是：

不要通过共享内存来通信，而要通过通信来共享内存。

这句话不是说不能用锁，而是鼓励优先用 channel 表达数据流和任务流；当多个 goroutine 必须访问同一份共享状态时，再用 sync.Mutex、sync.RWMutex 或 atomic 做保护。

channel 基础

channel 是 goroutine 之间传递数据的管道。

ch := make(chan int)

无缓冲 channel：

  • 发送方发送时，如果没有接收方，会阻塞。
  • 接收方接收时，如果没有数据，也会阻塞。
  • 适合同步交接任务。

有缓冲 channel：

ch := make(chan int, 10)
  • 缓冲区未满时发送不会阻塞。
  • 缓冲区为空时接收会阻塞。
  • 适合削峰和生产消费模型，但容量需要结合业务评估。

WaitGroup：等待一组 goroutine

var wg sync.WaitGroup

wg.Add(2)

go func() {
    defer wg.Done()
    doTaskA()
}()

go func() {
    defer wg.Done()
    doTaskB()
}()

wg.Wait()

注意点：

  • Add 要在启动 goroutine 前调用。
  • 每个 goroutine 退出前要 Done，建议配合 defer。
  • WaitGroup 只负责等待，不负责收集错误；需要错误传播时可以用 errgroup。

Mutex 和 channel 怎么选

场景 更适合
传递任务、事件、信号 channel
保护共享 map、计数器、状态对象 Mutex / RWMutex
单个数值的原子读写 atomic
多个 goroutine 执行并收集错误 errgroup

简单判断：

  • 传递所有权，用 channel。
  • 共享同一份数据，用锁。

三个 goroutine 轮流打印数字

这个题考察的是 channel 协作和退出控制。

package main

import (
    "fmt"
    "sync"
)

func main() {
    chans := []chan int{
        make(chan int),
        make(chan int),
        make(chan int),
    }

    var wg sync.WaitGroup
    wg.Add(3)

    for i := 0; i < 3; i++ {
        id := i
        go func() {
            defer wg.Done()
            for n := range chans[id] {
                if n > 100 {
                    close(chans[(id+1)%3])
                    return
                }

                fmt.Println(n)
                chans[(id+1)%3] <- n + 1
            }
        }()
    }

    chans[0] <- 1
    wg.Wait()
}

重点不在代码有多短，而是能说明：

  • channel 负责把执行权传给下一个 goroutine。
  • 退出时必须关闭下一个 channel，否则可能造成阻塞。
  • WaitGroup 保证主 goroutine 等待所有任务结束。

常见问题

1. goroutine 泄漏

如果 goroutine 一直阻塞在 channel、网络请求或锁上，且没有退出条件，就会泄漏。常见解决方式是使用 context.Context 控制取消。

2. deadlock

无缓冲 channel 发送和接收必须配对。如果所有 goroutine 都在等别人，runtime 会报 deadlock。

3. defer 参数求值

defer 的参数在注册时就会求值，多个 defer 按后进先出的顺序执行。

4. map 并发写

普通 map 不是并发安全的，并发读写需要加锁，或使用 sync.Map。

面试表达

可以这样总结：

Go 的并发核心是 goroutine 和 channel。channel 适合任务传递和信号同步，Mutex 适合保护共享状态。工程里我会特别关注 goroutine 的退出条件、channel 是否可能阻塞、WaitGroup 是否正确 Done、共享 map 是否加锁，以及是否需要用 context 做取消控制。
