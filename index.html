电话号码的字母组合

核心思路

跟前两道回溯题一个套路，就是用递归表示一种更高级的循环(迭代)，
定义结果集ans，暂存变量path来存储答案元素，定义字母表，开头两个空串便于映射
开始递归，如果当前已经走了n步，加入结果集并返回
否则，遍历digits对应的数字对应的字母表，加图path中开启下一轮递归，完成后pop恢复现场

触发点

看到“枚举所有组合”，想到回溯

易错点

忘记恢复现场，导致结果不对
这题要在主函数里判断digits是否为空，空的话直接返回空数组

复杂度

时间 O(n*4^n) n是digits长度，4^n是组合数量，每个组合需要O(n)的时间添加到结果集中
空间 O(n) path的长度为n，递归栈深度也是n

子集

核心思路

枚举子集的第1个数选谁，第2个数选谁……第n个数选谁，

将没选的结果直接加入结果集，再从当前位置开始枚举，枚举结束后恢复现场

触发点

看到“枚举所有子集”或者“需要枚举所有组合”，想到回溯

易错点

忘记恢复现场，导致结果不对

复杂度

时间 O(n*2^n) n是数组长度，2^n是子集数量，每个子集需要O(n)的时间添加到结果集中
空间 O(n) path的长度为n，递归栈深度也是n

我的收获

是否恢复现场与当前状态是否修改共享状态有关，修改了共享状态就要恢复现场，没修改就不需要恢复现场

全排列

核心思路

回溯，维护visited和path，递归中保存递归层数，等于nums大小时添加到结果集中，然后遍历nums，没有被访问的就添加到path中并标记为已访问，
递归下一层，递归下一层结束后标记为未访问，即回溯。

触发点

全排列很容易想到回溯

易错点

忘记回溯，导致结果不对
做递归类题目需要确定什么时候回溯，什么时候不回溯

复杂度

时间 O(n*n!) n是数组长度，n!是全排列数量，每个全排列需要O(n)的时间添加到结果集中
空间 O(n) path的长度为n，递归栈深度也是n

回答模板

我觉得自己有一个需要提升的地方，就是刚接触新任务时会偏谨慎，前期会想把细节考虑得比较完整。比如我之前做秒杀项目时，在下单链路改造上，我一开始会先花不少时间把 Redis 校验、MQ 异步下单和数据库落库之间的关系梳理清楚，再开始动手。这样虽然返工少，但前期启动会慢一点。后来我调整成先把主链路拆小，先做最小可运行版本，再逐步补细节，同时及时同步自己的阶段性理解。这样既保证了质量，也提高了推进效率。

Redis

常用数据结构和操作函数

1. String

最常用，适合存字符串、数字、JSON。

常用命令：

  • SET key value：设置值
  • GET key：取值
  • MSET k1 v1 k2 v2：一次设置多个值
  • MGET k1 k2：一次取多个值
  • INCR key：数字加 1
  • DECR key：数字减 1
  • SETEX key seconds value：设置值并加过期时间
  • SETNX key value：key 不存在才设置，常用于加锁

2. Hash

适合存对象、字段集合。

常用命令：

  • HSET key field value：设置字段值
  • HGET key field：取某个字段值
  • HMGET key f1 f2：取多个字段值
  • HGETALL key：取全部字段和值
  • HDEL key field：删除字段
  • HINCRBY key field n：字段数字加 n

3. List

双端列表，适合队列、消息流。

常用命令：

  • LPUSH key v1 v2：从左边放入
  • RPUSH key v1 v2：从右边放入
  • LPOP key：从左边取出
  • RPOP key：从右边取出
  • LRANGE key start end：查看一段数据
  • LLEN key：看长度

4. Set

无序、元素唯一，适合去重。

常用命令：

  • SADD key v1 v2：添加元素
  • SREM key v1：删除元素
  • SMEMBERS key：查看全部元素
  • SISMEMBER key v：判断元素在不在
  • SCARD key：看元素个数
  • SINTER k1 k2：求交集
  • SUNION k1 k2：求并集

5. ZSet

有序集合，带分数，适合排行榜。

常用命令：

  • ZADD key score value：添加元素和分数
  • ZREM key value：删除元素
  • ZRANGE key 0 -1：按分数从小到大查看
  • ZREVRANGE key 0 -1：按分数从大到小查看
  • ZSCORE key value：看元素分数
  • ZRANK key value：看正序排名
  • ZINCRBY key n value：分数加 n

6. Bitmap

按位存储，适合签到、活跃统计。

常用命令：

  • SETBIT key offset 1：设置某一位
  • GETBIT key offset：查看某一位
  • BITCOUNT key：统计 1 的个数
  • BITOP op dest k1 k2：做位运算

7. HyperLogLog

适合做去重计数、UV 统计。

常用命令：

  • PFADD key v1 v2：添加数据
  • PFCOUNT key：统计数量
  • PFMERGE newKey k1 k2：合并统计

8. Stream

消息流，适合消息队列、消费组。

常用命令：

  • XADD key * field value：添加消息
  • XRANGE key - +：查看消息范围
  • XREAD STREAMS key id：读取消息
  • XGROUP CREATE key group 0：创建消费组
  • XREADGROUP GROUP g c STREAMS key >：按消费组读消息
  • XACK key group id：确认消息已消费

通用命令

几乎所有类型都会用到。

常用命令：

  • DEL key：删除 key
  • EXPIRE key seconds：设置过期时间
  • TTL key：查看剩余过期时间
  • EXISTS key：判断 key 是否存在
  • TYPE key：查看 key 的类型
  • SCAN 0：分页查 key

一句话速记

  • String：值
  • Hash：对象
  • List：队列
  • Set：去重集合
  • ZSet：排行榜
  • Bitmap：位统计
  • HyperLogLog：基数统计
  • Stream：消息队列

前缀树

题目名：前缀树

1. 题型标签

字符串，前缀，字典树

2. 核心思路

Trie是一种数据结构存储有大量公共前缀的字符串。
每个节点维护：

  1. son：指向下一个字符
  2. isEnd：当前节点是否是某个单词结尾

insert(word)：逐字符往下走，不存在就创建，最后把 isEnd 设为 true
search(word)：逐字符查找，最后还要判断 isEnd 是否为 true
startsWith(prefix)：逐字符查找，只要路径存在就返回 true

3. 触发点

看到“多次查询某个单词/前缀是否存在”
看到“很多字符串有公共前缀”
看到“需要动态插入再查询”

4. 易错点

忘记维护isEnd

5. 复杂度

时间：insert/startWith/search都是O(L)L是字符串长度
空间 O(nL) n是单词数量，L是单词最大长度

6. 我的收获

看到前缀查询+多次查找/插入，想到Trie

Sql50

sql常用工具

写 SQL 题时，真正高频的工具不多，记住下面几个就够了。

1. 聚合函数

  • COUNT(*)：统计行数
  • SUM(col)：求和
  • AVG(col)：求平均
  • MAX(col) / MIN(col)：最大值 / 最小值

2. CASE WHEN

做条件判断、分类统计时最常用。

3. IFNULL() / COALESCE()

处理空值，避免结果是 NULL。

4. ROW_NUMBER()

分组排名、取每组第一条时非常常见。

小结

刷题时先熟练这 4 个：

  • 聚合函数：做统计
  • CASE WHEN：做条件
  • IFNULL() / COALESCE()：处理空值
  • ROW_NUMBER()：做分组排名
