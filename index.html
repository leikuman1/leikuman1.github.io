概念解释

  • 系统调用:当程序需要创建或使用OS提供的对象时,一般需要os提供的系统调用才能实现,与此同时,系统调用让计算机从用户态切换到内核态再切换回来会造成一定的时间开销.
  • 进程,线程,协程:进程是操作系统资源分配的基本单位,线程是操作系统进行cpu调度的基本单位,而协程是运行在线程之上的,更轻量的用户态执行单元,通常由语言的runtime或框架调度.
    进程 是一个正在运行的程序实例。每个进程有自己独立的地址空间、内存、文件描述符等资源，进程之间相互隔离，所以安全性和稳定性比较好。但进程创建、销毁和切换的成本比较高，进程间通信也相对复杂，比如要通过管道、消息队列、共享内存、Socket 等方式。

线程 是进程内部的执行流。一个进程可以包含多个线程，多个线程共享进程的堆内存、全局变量、文件等资源，但每个线程有自己的栈、程序计数器和寄存器上下文。线程比进程更轻量，线程之间通信更方便，但是因为共享内存，所以需要考虑线程安全问题，比如锁、CAS、死锁、竞态条件等。

协程 是比线程更轻量的执行单元，通常由程序语言的运行时调度，而不是直接由操作系统调度。协程运行在线程之上，创建和切换成本更低，适合大量高并发 I/O 场景。比如 Go 里的 goroutine、Python 的 async/await，都可以看作协程相关的实现。

  • 临界区:一段访问共享资源的代码区域。多个线程/进程如果同时进入这段代码，可能会导致数据错误。

这里channel是goroutine之间传递数据的管道,go推荐的并发思想是”不要通过共享内存来通信，而要通过通信来共享内存”.也就是尽量让goroutine之间用channel传递数据,而不是大家都去抢同一个变量.
channel分为无缓冲channel和有缓冲channel

  1. 往无缓冲 channel 写数据，但没人接收，会阻塞，严重时会 deadlock。从无缓冲channel中接受数据,如果channel中没有,会一直阻塞

  2. 有缓冲channel在发送方发送数据没人接受时会先暂存到缓冲区,缓冲区满了就阻塞.接受方收不到数据也是一直阻塞
    PS:除了chanel，go中还可以用sync包中的Mutex,RWMutex,atomic,map等进行通信,其中atomic是对单个变量的原子读写操作,Mutex相对于atomic,更适合对变量判断+修改的复合逻辑,相对于更适合生产-消费模型的channel,更适合保护临界区.
    channel 适合“传递数据/任务/信号”,mutex 适合“保护共享数据”
    传递所有权，用 channel；
    共享同一份数据，用 mutex。

  3. defer 会把函数调用延迟到当前函数结束前执行。

  4. 多个 defer 按后进先出的顺序执行，语义上类似栈。

  5. defer 的参数在注册 defer 时就会求值。

sync.WaitGroup的作用是:等待一组goroutine执行完毕再退出,常用方法有
wg.Add(3) // 计数器 +3，表示有 3 个任务要等
wg.Done() // 计数器 -1，表示一个任务完成了
wg.Wait() // 阻塞等待，直到计数器变成 0
除了sync.wr,还可以使用以下方法实现等待一组goroutine完成

  1. 用channel收集完成信号
  2. 用errgroup,相当于加强版的WaitGroup,可以同时等待一组goroutine完成,还可以收集错误信息
    func main() {
        oddChan := make(chan int)
        evenChan := make(chan int)

        var wg sync.WaitGroup
        wg.Add(2)

        go func() {
            defer wg.Done()

            for i := 1; i <= 100; i += 2 {
                <-oddChan
                fmt.Printf("odd: %v\n", i)
                evenChan <- i
            }
        }()

        go func() {
            defer wg.Done()

            for i := 2; i <= 100; i += 2 {
                <-evenChan
                fmt.Printf("even: %v\n", i)
                if i == 100 {
                    return
                }
                oddChan <- i
            }
        }()
        oddChan <- 1
        wg.Wait()
}

相向双指针思想

一般用于找组合问题,比如在一个数组中找那些元素相加等于target,可以组成三角形之类的.
方法:在数组有序的前提下,通过指针以O(1)的时间获取O(n)的信息,达到比枚举更优的时间复杂度.比如当l+r>target时,可以判断[r,n-1]加l都大于target,故可以r–判断下一组,反之同理.

代码模板

    class Solution {
    public:
        vector<vector<int>> ans;
        vector<vector<int>> threeSum(vector<int>& nums) {
            sort(nums.begin(),nums.end());
            int n=nums.size();
            //outside loop
            for(int i=0;i<n-2;++i){
                //inside two point
                //nums[j]+nums[k]=-nums[i]
                if(i>0&&nums[i]==nums[i-1]){
                    continue;
                }
                int tmp=-nums[i];
                for(int j=i+1,k=n-1;j<k;){
                    if(nums[j]+nums[k]>tmp){
                        k--;
                    } else if(nums[j]+nums[k]<tmp){
                        j++;
                    } else {
                        ans.push_back({nums[i],nums[j],nums[k]});
                        while(j<k&&nums[j]==nums[j+1]){
                            j++;
                        }
                        while(k>j&&nums[k]==nums[k-1]){
                            k--;
                        }
                        j++;k--;
                    }
                }
            }
            return ans;
        }
    };

注意这里循环最里面的else,即更新ans后的去重操作,其目的是去重,去掉加入ans集的nums[k],nums[j].比如当前j是1,后面是1,2,3,就要让j指向2.
以j为例子,可以先++再判断和前面的数是否相同,也可以先判断和后面的数是否相同,最后再++.

相似题型

2824 统计小于目标的下标对数目
没什么好说的,套模板改成小于就行,大于就k–,小于记录答案然后j++
就是合适后再修改变量试探,看能不能继续符合条件,这种思想非常重要.

16 最接近的三数之和
套模板就行,枚举i,如果sum>target就k–,否则j++,每轮都更新一遍ans

18 四数之和
相向双指针只能维护两个,所以最外层枚举i,内一层枚举j,内二层枚举k1,k2
这里需要注意j的去重条件是j>i+1&&nums[j]==nums[j-1],代表除了刚进入循环的第一次,后面如果枚举的数和前一个相同就跳过,思想和i去重相同

611 有效三角形个数
这里要转变思路,如果一开始就套模板外层枚举i,内层枚举j,k.就会发现
nums[i]+nums[j]>nums[k]时,既可以k++,也可以j–
nums[i]+nums[j]<nums[k]时,既可以k–,也可以j++
造成这种情况的根本原因是j和k不在等式的同一边,于是单调性就出了问题,以前遇到的问题,jk都在同一边,每种情况都只能调整一个变量,要么j增要么k-.
所以这里只能枚举k,ij当做双指针或使用同向双指针,即滑动窗口

三类高频提问

完成了第一章的验收后，我们将要开启下一轮开发，在那之前要熟悉三类提问

理解类：这个项目在做什么

请用人话解释这个项目目前的结构。
告诉我主页入口、xxx功能相关代码、样式相关文件分别大概在哪。
不要展开太深。

定位类: 我想修改功能x,相关代码在哪

我想修改首页首屏的一句话介绍和主按钮文案。
请先告诉我这两处分别在哪个文件里，再给出修改建议。

约束类: 只改这一处,不要修改其他地方

请只修改聊天框的引导语，不要改布局，不要新增模块，也不要调整配色。

现在我们要进行前端页面的修改,因为前端是用户最直接接触的层级,就像看人的第一印象一样,下面介绍三个最优先的修改

三个前端页面修改

首先调整首页布局,明确页面主次关系,最重要的是你想要别人一打开页面,第一眼看到的是什么,哪些元素最重要,哪些元素可以稍微推后.

请先优化首页首屏排版。
目标是让名字、一句话介绍和主要按钮更有主次，聊天入口更容易被注意到。
不要新增模块，先只调整布局、间距和元素优先级。

其次颜色和字体要统一,确定主色系,规定一系列这个色系相关的颜色并且按照关系分配给各级元素.
字体也要确定,标题的字体用什么,正文和辅助信息的字体用什么都区分开来,还要确保字体和首页主题契合,看着没有违和感.

最后是区域和留白
很多新手容易忽略这一层，因为它不像按钮颜色那样显眼，但它对作品感影响很大。区块之间有没有呼吸感，信息是不是挤在一起，哪一段是主信息、哪一段是辅助信息，访客是不是一眼能扫出结构，这些都会决定页面是不是好读。很多时候，你不需要加新内容，只需要把已有内容重新拉开层次，页面就会立刻更像作品。
