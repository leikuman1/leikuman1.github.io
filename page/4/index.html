统一构建router

在FastAPI中，我们可以通过APIRouter来统一构建路由，这样可以将不同的路由分组，方便管理和维护。

比如

from fastapi import APIRouter
router = APIRouter(prefix="/api/news", tags=["news"])
@router.get("/categories")
async def get_categories():
    return {"msg": "success"}

这里前缀/api/news表示这个路由的公共前缀，tags=[“news”]表示这个路由的标签，可以在文档中进行分类展示。
然后在主应用中引入这个router，如

app.include_router(news.router)

这样就可以将这个router中的所有路由都包含到主应用中，并且自动添加前缀/api/news。

FastAPI 2026/4/25

增加

先新建一个DTO类来接收请求体参数：

from pydantic import BaseModel
class ItemCreate(BaseModel):
    name: str
    description: str
    price: float

然后在路由函数中使用这个DTO类来接收请求体参数，并把它转换为ORM模型对象来进行数据库操作：

@app.post("/items/")
async def create_item(item: ItemCreate, db: AsyncSession = Depends(get_db)):
    item_obj = Item(**item.dict())
    db.add(item_obj)
    await db.commit()
    await db.refresh(item_obj)
    return item_obj

这里的item: ItemCreate表示这个参数是一个请求体参数，FastAPI会自动将请求体中的JSON数据解析成一个ItemCreate对象，并传递给create_item函数。然后我们通过item.dict()方法将DTO对象转换为一个字典，再通过**操作符将字典解包成关键字参数来创建一个ORM模型对象item_obj。最后我们将这个对象添加到数据库会话中，提交事务，并刷新对象以获取数据库生成的ID等字段，最后返回这个对象。

注意还要先定义好ORM模型类Item，并且在数据库中创建好对应的表。就是那个类定义里有__tablename__ = “items”的那个类。

FastAPI 2026/4/25

查询

先来看看简单的查询方式

from sqlalchemy import select
@app.get("/items/")
async def read_items(db: AsyncSession = Depends(get_db)):
    result = await db.execute(select(Item)).where(Item.name == "item1")
    items = result.scalars().all()
    return items

这里可以总结一下查询的一般方式：await db.execute(select(模型).where(条件))，然后通过scalars()方法把结果转换为指定对象列表，最后通过all()方法获取所有结果。

模糊查询和多条件查询

@app.get("/items/")
async def read_items(db: AsyncSession = Depends(get_db)):
    result = await db.execute(select(Item).where(Item.name.like("%item%")|Item.price > 10))
    items = result.scalars().all()
    return items

跟mysql里一样，like表示模糊查询，%表示任意字符，|表示或，&表示且。

聚合和分页

@app.get("/items/")
async def read_items(db: AsyncSession = Depends(get_db), page: int = 0, page_size: int = 10):
    result = await db.execute(select(func.count(Item.id)))
    total = result.scalar()
    skip = (page - 1) * page_size
    result = await db.execute(select(Item).offset(skip).limit(page_size))
    items = result.scalars().all()
    return {"total": total, "items": items}

yield and await

yield 是一个生成器函数的关键字，它可以暂停函数的执行，并返回一个值给调用者。当函数再次被调用时，它会从上次暂停的地方继续执行，而不是从头开始执行。可以用来惰性求值，慢慢处理大量数据，防止内存溢出。

await 是一个异步函数的关键字，它可以暂停函数的执行，等待一个异步操作完成。当异步操作完成后，函数会继续执行，而不会阻塞其他代码的执行。可以用来处理IO密集型任务，提高程序的性能。
如果调用一个异步函数不使用await，那么这个函数会返回一个协程对象，而
函数结果不一定执行完成，所以在使用异步函数时，必须使用await来等待它的结果。

**总结一下就是调用异步函数必须使用await来等待它的结果，而yield是生成器函数的关键字，可以暂停函数的执行，并返回一个值给调用者。

在路由中使用ORM

先创建一个会话工厂

from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker
DATABASE_URL = "mysql+aiomysql://user:password@localhost/dbname"
engine = create_engine(DATABASE_URL)
Async_SessionLocal = async_sessionmaker(autocommit=False, autoflush=False, bind=engine)

async def get_db():
    async with Async_SessionLocal() as session:
        try:
            yield session
            await session.commit()
        except Exception as e:
            await session.rollback()
            raise e
        finally:
            await session.close()

这个函数会创建一个数据库会话，并在使用完后自动提交事务或回滚事务，并关闭会话。

在路由中使用这个函数来获取数据库会话：

from fastapi import Depends
@app.get("/items/")
async def read_items(db: AsyncSession = Depends(get_db)):
    result = await db.execute(select(Item))
    items = result.scalars().all()
    return items

这里的Depends(get_db)表示这个参数是一个依赖项，FastAPI会自动调用get_db函数来获取数据库会话，并将其作为参数传递给read_items函数。这样我们就可以在路由中使用ORM来操作数据库了。

中间件和依赖注入
FastAPI 2026/4/25

中间件

中间件是一个函数，它可以在请求被处理之前或之后执行一些操作。中间件可以用于处理跨域请求、日志记录、身份验证等。类似于Spring中的AOP思想。

可以通过middleware装饰器来定义一个中间件函数，如：

from fastapi import FastAPI, Request
from fastapi.middleware.cors import CORSMiddleware
app = FastAPI()
@app.middleware("http")
async def add_process_time_header(request: Request, call_next):
    response = await call_next(request)
    response.headers["X-Process-Time"] = "0.1s"
    return response

这里的add_process_time_header函数是一个中间件函数，它在请求被处理之前执行，调用call_next(request)来继续处理请求，并在响应中添加一个自定义的头部X-Process-Time。

这里还需要注意，如果有多个中间件，执行顺序是按照定义的顺序执行的。
而且执行方式类似于递归调用，先执行第一个中间件，调用call_next(request)来继续处理请求，进入下一个中间件，直到最后一个中间件处理完请求后返回响应，然后依次返回到上一个中间件，最后返回给客户端。
所以定义越早的中间件越先执行，定义越晚的中间件越后执行，但是返回响应的顺序是相反的，定义越早的中间件越后返回，定义越晚的中间件越先返回。

依赖注入

依赖注入是一种设计模式，它允许我们将一个对象的依赖关系从对象本身中分离出来，使得代码更加模块化和可测试。在FastAPI中，依赖注入是通过Depends函数来实现的。说人话就是复用相同的代码。

例如，我们有一个函数get_db()来获取数据库连接，我们可以将这个函数作为一个依赖注入到其他函数中，如：

from fastapi import Depends
def get_db():
    db = "数据库连接"
    try:
        yield db
    finally:
        print("关闭数据库连接")
@app.get("/items/")
async def read_items(db: str = Depends(get_db)):
    return {"db": db}

这里的get_db函数是一个依赖函数，它返回一个数据库连接。在read_items函数中，我们使用Depends(get_db)来注入这个依赖，这样当我们调用read_items函数时，FastAPI会自动调用get_db函数来获取数据库连接，并将其作为参数传递给read_items函数。

依赖注入的好处是可以将公共的代码抽离出来，避免重复代码，提高代码的可维护性和可测试性。

初试FastAPI
FastAPI 2026/4/25

路由

路由是url地址和函数之间的映射关系
新建python的FastAPI项目,在main.py中添加以下内容：

from fastapi import FastAPI
//创建FastAPI应用实例
app = FastAPI()

//定义一个根路由，返回一个简单的JSON响应
//这里的@app.get("/")是一个装饰器，表示这个函数是处理GET请求的，并且路径是"/"，也就是根路径。当访问这个路径时，异步函数read_root会被调用，返回一个JSON对象{"Hello": "World"}。
@app.get("/")
//相当于@RequestMapping("/")，默认是GET请求
async def read_root():
    return {"Hello": "World"}

路由参数

路由参数分为三种：路径参数、查询参数、请求体参数

  • 路径参数：直接在路径中定义参数，是url的一部分，如
@app.get("/items/{item_id}")
async def read_item(item_id: int):
    return {"item_id": item_id}

另外，FastAPI还有Path注解可以对路径参数进行验证和设置默认值，如：

@app.get("/items/{item_id}")
async def read_item(item_id: int = Path(..., title="The ID of the item to get", ge=1)):
    return {"item_id": item_id}

这里的Path(…)表示这个参数是必填的，title是参数的描述，ge=1表示这个参数必须大于等于1。

  • 查询参数：在url中以?key=value的形式传递参数，如
@app.get("/items/")
async def read_items(
    skip: int = query(0, title="Number of items to skip", ge=0),
    limit: int = 10):
    return {"skip": skip, "limit": limit}

这里的注解query(0, title=”Number of items to skip”, ge=0)表示这个参数是可选的，默认值是0，title是参数的描述，ge=0表示这个参数必须大于等于0。

  • 请求体参数：通过请求体传递参数，通常是POST、PUT、PATCH等请求，如
    根据HTTP协议，一个请求分为三部分：请求行、请求头、请求体。
    请求行：包含请求方法（GET、POST等）、请求路径和HTTP版本。
    请求头：包含一些元信息，如Content-Type、Authorization等。
    请求体：包含实际的数据，如JSON、表单数据等。
from pydantic import BaseModel
class Item(BaseModel):
    name: str
    description: str = None

@app.post("/items/")
async def create_item(item: Item):
    return item

这里的Item是一个Pydantic模型，定义了请求体的结构。当发送一个POST请求到/items/路径时，FastAPI会自动将请求体中的JSON数据解析成一个Item对象，并传递给create_item函数。

同样的，FastAPI还有Body注解可以对请求体参数进行验证和设置默认值，如：

@app.post("/items/")
async def create_item(item: Item = Body(..., title="The item to create")):
    return item

这里的Body(…)表示这个参数是必填的，title是参数的描述。

另外，pydantic中还有Field注解可以对模型字段进行验证和设置默认值，如：

class Item(BaseModel):
    name: str = Field(..., title="The name of the item", max_length=100)
    description: str = Field(None, title="The description of the item", max_length=255)

这里的Field(…)表示这个字段是必填的，title是字段的描述，max_length是字段的最大长度。

响应类型

默认情况下，FastAPI会将返回的Python对象转换成JSON格式的响应，省去了手动序列化的步骤，而且支持多种响应类型，如JSON、HTML、文件等。

指定响应类型的方法有两种：

  • 在装饰器中指定，如HTMLResponse、FileResponse等，如
from fastapi.responses import HTMLResponse
@app.get("/html/", response_class=HTMLResponse)
async def get_html():
    html_content = "<html><body><h1>Hello, World!</h1></body></html>"
    return HTMLResponse(content=html_content, status_code=200)
  • 在函数中返回特定的响应对象，如JSONResponse、FileResponse等，如
from fastapi.responses import fileResponse
@app.get("/file/")
async def get_file():
    file_path = "path/to/your/file.txt"
    return FileResponse(path=file_path, filename="file.txt", media_type="text/plain")

这里的FileResponse会将指定路径的文件作为响应返回，filename是下载时的文件名，media_type是文件的MIME类型。

这两种方法各有优缺点，第一种方法更简洁，严格，适合简单的响应类型；第二种方法更灵活，适合需要自定义响应内容或状态码的情况。

还有一种方法可以自定义响应类型，就是用基于Pydantic的模型来定义响应结构，如：

from pydantic import BaseModel
class ItemResponse(BaseModel):
    name: str
    description: str = None

@app.get("/items/{item_id}", response_model=ItemResponse)
async def read_item(item_id: int):
    item = get_item_from_database(item_id)
    return ItemResponse(name=item.name, description=item.description)

异常处理

FastAPI提供了HTTPException类来处理HTTP异常，可以在路由函数中抛出这个异常来返回特定的错误响应，如：

from fastapi import HTTPException
@app.get("/items/{item_id}")
async def read_item(item_id: int):
    item = get_item_from_database(item_id)
    if item is None:
        raise HTTPException(status_code=404, detail="Item not found")
    return item

这里的HTTPException(status_code=404, detail=”Item not found”)表示当item为None时，抛出一个404 Not Found的错误响应，detail是错误的详细信息.

1.引入依赖

在requirements.txt中添加以下依赖：

pymysql

pymysql是一个纯Python的MySQL客户端库，sqlalchemy是一个ORM（对象关系映射）工具，pydantic-settings用于管理配置,可以通过环境变量或配置文件来设置数据库连接参数。

这里多一嘴，和Java，C++相比，python是动态类型语言，灵活性更高，这是python的设计哲学之一，但是在开发大型项目中，动态类型容易导致类型错误，所有有了pydantic这样的库来提供类型检查和数据验证，pydantic-settings是pydantic的一个扩展，专门用于管理应用程序的配置，可以从环境变量、配置文件等多种来源加载配置.

2.配置数据库连接

现在项目根目录里新建一个.env文件，添加以下内容：

DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=123456
DB_NAME=restaurant

这些环境变量将用于配置数据库连接。

再创建一个config.py文件，添加以下内容：

from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    db_host: str
    db_port: int
    db_user: str
    db_password: str
    db_name: str

    model_config = SettingsConfigDict(
        env_file=".env",
        env_file_encoding="utf-8",
        extra="ignore",
    )

    @property
    def database_url(self) -> str:
        return (
            f"mysql+pymysql://{self.db_user}:{self.db_password}"
            f"@{self.db_host}:{self.db_port}/{self.db_name}?charset=utf8mb4"
        )


settings = Settings()

这个配置类会从.env文件中读取数据库连接参数，并提供一个database_url属性来生成数据库连接字符串。

3. 创建数据库模型

在models/下根据数据库表结构创建所需要的数据

class Menu(Base):
    __tablename__ = "menus"

    id: Mapped[int] = mapped_column(primary_key=True, autoincrement=True)
    name: Mapped[str] = mapped_column(String(100), unique=True, nullable=False)
    category: Mapped[str] = mapped_column(String(50), nullable=False)
    price: Mapped[Decimal] = mapped_column(Numeric(10, 2), nullable=False)
    description: Mapped[str | None] = mapped_column(String(255), nullable=True)
    status: Mapped[int] = mapped_column(nullable=False, default=1)
    created_at: Mapped[datetime] = mapped_column(DateTime, server_default=func.now(), nullable=False)
    updated_at: Mapped[datetime] = mapped_column(DateTime, server_default=func.now(), onupdate=func.now(), nullable=False)

把表结构映射到具体的数据，有点像orm

再在session.py中添加以下内容：

from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker, Session

from app.core.config import settings


engine = create_engine(
    settings.database_url,
    echo=True,
    pool_pre_ping=True,
)

SessionLocal = sessionmaker(
    bind=engine,
    autoflush=False,
    autocommit=False,
    expire_on_commit=False,
)


def get_db():
    db: Session = SessionLocal()
    try:
        yield db
    finally:
        db.close()

这个文件创建了一个数据库引擎，并定义了一个SessionLocal类来管理数据库会话。get_db函数是一个依赖项，可以在FastAPI的路由中使用，以便在请求期间获取数据库会话。

4. 使用数据库

在FastAPI的路由中，我们可以使用get_db依赖项来获取数据库会话，并执行数据库操作.

至此，我们已经成功地将FastAPI应用程序连接到MySQL数据库，并且可以使用SQLAlchemy进行数据库操作了。
